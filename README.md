# MusicBot

Небольшой музыкальный Discord-бот на Python. Бот ищет треки на Hitmo, показывает несколько результатов пользователю, воспроизводит выбранный трек в голосовом канале, поддерживает очередь и автоматически выходит из voice-канала после периода бездействия.

> Текущий провайдер использует HTML-разметку Hitmo, а не официальный API. Если сайт изменит структуру страницы, парсер в `music_bot/providers/hitmo.py` может потребовать обновления.

## Возможности

- `/play <запрос>` — поиск трека и выбор из нескольких результатов кнопками.
- `/queue` — показать текущий трек и очередь.
- `/skip` — пропустить текущий трек.
- `/stop` — остановить воспроизведение и очистить очередь.
- `/join` — подключить бота к голосовому каналу пользователя.
- `/leave` — отключить бота от голосового канала.
- `/ping` — проверить, что бот отвечает.
- `/playtest` — воспроизвести локальный `test.mp3` для диагностики.
- Автоматический переход к следующему треку.
- Автоматическое отключение от voice-канала после простоя.
- Отдельная очередь для каждого Discord-сервера на уровне `MusicPlayer`.

## Требования

- Windows 10/11 или macOS. Linux также должен работать при наличии тех же зависимостей.
- Python 3.12 рекомендуется для текущей сборки.
- FFmpeg должен быть установлен и доступен через `PATH`.
- Discord-приложение с ботом, добавленным на сервер через **Guild Install**.
- Доступ к Discord API/Gateway и к источнику музыки из сети.

Проверка FFmpeg:

```powershell
ffmpeg -version
```

## Установка

### Windows 10/11

Создай виртуальное окружение:

```powershell
python -m venv venv
```

В PowerShell при необходимости разреши активацию скриптов для текущего процесса:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Активируй окружение:

```powershell
.\venv\Scripts\Activate.ps1
```

Установи зависимости:

```powershell
pip install -r requirements.txt
```

FFmpeg на Windows должен быть установлен отдельно и доступен через `PATH`:

```powershell
ffmpeg -version
```

### macOS

Проект не содержит Windows-специфичной логики и может запускаться на macOS без изменений исходного кода. Основные отличия — установка системных зависимостей и команды активации виртуального окружения.

Рекомендуемый вариант — Homebrew. Установи Python 3.12, FFmpeg и Opus:

```bash
brew install python@3.12 ffmpeg opus
```

Проверь установку:

```bash
python3.12 --version
ffmpeg -version
```

Создай виртуальное окружение из корня проекта:

```bash
python3.12 -m venv venv
```

Активируй его:

```bash
source venv/bin/activate
```

Установи Python-зависимости:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Создай `.env` из примера:

```bash
cp .env.example .env
```

Заполни `DISCORD_TOKEN` и `GUILD_ID`, затем запусти бота:

```bash
python bot.py
```

Для выхода из виртуального окружения:

```bash
deactivate
```

#### macOS: возможная проблема с Opus

Текущий плеер использует `discord.FFmpegPCMAudio`, поэтому Discord должен иметь доступ к библиотеке Opus. Обычно после `brew install opus` библиотека определяется автоматически. Если бот подключается к voice-каналу, но воспроизведение падает с ошибкой `OpusNotLoaded`, сначала проверь наличие библиотеки:

```bash
brew list opus
```

Также проверь, что проект запущен именно из активированного `venv`, а `ffmpeg` виден из того же терминала:

```bash
which python
which ffmpeg
```

#### Apple Silicon и Intel

Сам Python-код архитектурно независим от процессора. Homebrew предоставляет готовые пакеты FFmpeg и Opus для современных Mac на Apple Silicon и поддерживаемых Intel-моделях. Важно лишь не смешивать зависимости разных архитектур в одном `venv`.

## Настройка `.env`

Скопируй `.env.example` в `.env` и заполни значения:

```env
DISCORD_TOKEN=your_bot_token_here
GUILD_ID=123456789012345678
IDLE_TIMEOUT_SECONDS=600
SEARCH_LIMIT=5
```

Параметры:

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `DISCORD_TOKEN` | Секретный токен Discord-бота | обязательна |
| `GUILD_ID` | ID Discord-сервера, на котором синхронизируются slash-команды | обязательна |
| `IDLE_TIMEOUT_SECONDS` | Через сколько секунд простоя бот выйдет из voice-канала | `600` |
| `SEARCH_LIMIT` | Сколько результатов поиска показать пользователю | `5` |

Не добавляй настоящий `.env` в Git. Он уже исключён через `.gitignore`.

## Запуск

После активации `venv` команда одинакова на Windows и macOS:

```text
python bot.py
```

При успешном запуске в консоли появится примерно:

```text
Slash-команды зарегистрированы: ...
Бот запущен: MusicBot#....
```

## Совместимость Windows / macOS

Логика проекта одинакова на обеих системах:

- Discord API и slash-команды работают одинаково;
- очередь и idle-disconnect используют `asyncio` и не зависят от ОС;
- Hitmo-провайдер выполняет обычные HTTP-запросы через `httpx`;
- FFmpeg запускается как внешний процесс через `discord.py`;
- пути к файлам в основном коде не захардкожены под Windows.

Отличаются только установка системных программ и путь виртуального окружения (`venv\Scripts` на Windows против `venv/bin` на macOS).

## Обычный сценарий использования

1. Пользователь заходит в голосовой канал.
2. Выполняет:

```text
/play Linkin Park Numb
```

3. Бот запрашивает страницу поиска Hitmo.
4. Из найденных карточек треков извлекаются исполнитель, название, длительность и URL аудиопотока.
5. Бот показывает результаты и кнопки выбора.
6. Пользователь нажимает нужный номер.
7. Если музыка сейчас не играет — трек запускается сразу.
8. Если музыка уже играет — выбранный трек добавляется в очередь.
9. После окончания текущего трека автоматически запускается следующий.
10. Если очередь закончилась и бот не используется в течение `IDLE_TIMEOUT_SECONDS`, он выходит из voice-канала.

## Команды

### `/play <query>`

Ищет музыку. По умолчанию выводится до пяти вариантов вида:

```text
1. Linkin Park — Numb · 3:07
2. Linkin Park — Numb (Live) · 3:44
...
```

Выбрать результат может только пользователь, который запустил поиск. Кнопки активны 60 секунд.

### `/queue`

Показывает текущий трек и все ожидающие треки.

### `/skip`

Останавливает текущий трек. Callback плеера автоматически запускает следующий элемент очереди.

### `/stop`

Останавливает текущий трек и полностью очищает очередь.

### `/join`

Подключает бота к голосовому каналу пользователя. Если музыка не запускается, начинается таймер простоя.

### `/leave`

Очищает состояние плеера для сервера и отключает бота от voice-канала.

### `/playtest`

Диагностическая команда. Ищет `test.mp3` в корне проекта и проигрывает его напрямую через FFmpeg, без Hitmo.

## Сетевой поток

Упрощённо воспроизведение выглядит так:

```text
Пользователь
   │
   │ /play запрос
   ▼
Discord API
   │
   ▼
MusicCog
   │
   ▼
HitmoProvider
   │ HTTP GET /search?q=...
   ▼
Hitmo HTML
   │
   │ data-musmeta
   ▼
TrackCandidate[]
   │
   ▼
TrackSelectView
   │ пользователь нажимает кнопку
   ▼
MusicPlayer
   │
   ▼
FFmpegPCMAudio(stream_url)
   │
   ▼
Discord Voice
```

## Важные особенности

### Hitmo не имеет стабильного API в текущей реализации

Провайдер ищет элементы:

```text
li.tracks__item.track[data-musmeta]
```

и разбирает JSON из `data-musmeta`. Если Hitmo изменит HTML-разметку, чаще всего потребуется исправить только `music_bot/providers/hitmo.py`.

### URL аудио не хранится в очереди отдельно от трека

`TrackCandidate` содержит `stream_url`, полученный при поиске. Этот URL передаётся FFmpeg в момент запуска трека. Если источник начнёт выдавать короткоживущие ссылки, архитектуру стоит изменить так, чтобы URL обновлялся непосредственно перед воспроизведением.

### Очередь хранится в памяти

После перезапуска Python-процесса текущий трек и очередь теряются. База данных сейчас не используется.

### Бот остаётся Online после выхода из voice

Idle-таймер отключает только голосовое соединение. Сам Python-процесс продолжает работать, поэтому бот остаётся доступным для новых команд.

## Диагностика

Если бот Online, но не подключается к voice:

- убедись, что приложение установлено на сервер через **Guild Install**, а не только как User Install;
- проверь права `View Channel`, `Connect`, `Speak`;
- проверь, что Discord-трафик доступен из Python-процесса.

Если FFmpeg не найден:

```powershell
where.exe ffmpeg
python -c "import shutil; print(shutil.which('ffmpeg'))"
```

Если поиск перестал возвращать треки, первым делом проверь текущую разметку Hitmo и `data-musmeta`.
